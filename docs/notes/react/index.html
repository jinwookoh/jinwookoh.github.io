React

컴포넌트와 렌더링 모델, Hooks, 상태 설계, 데이터 페칭, 폼·라우팅, React 19의 Actions와 Server Components, 테스트와 배포.

10편

기초

  1. 1React란 — 컴포넌트·JSX·렌더링 모델React는 UI를 상태의 함수로 선언하고, 트리거·렌더·커밋 단계로 DOM을 갱신하는 라이브러리다
  2. 2Props·State·이벤트부모가 내려주는 읽기 전용 입력(props), 컴포넌트가 기억하는 값(state), 그리고 둘을 잇는 이벤트 핸들러의 역할 구분

Hooks와 상태

  1. 3useState·useEffect — 상태와 부수 효과useState는 렌더링 사이에 값을 보존하고, useEffect는 React 밖의 시스템과 동기화할 때만 쓴다.
  2. 4useRef·useMemo·useCallback과 렌더링 성능리렌더링 사이에 값·계산·함수를 어떻게 유지하고, 언제 메모이제이션이 실제 성능 이득이 되는지 정리한다.
  3. 5Context·useReducer·상태 설계prop drilling은 Context로, 흩어진 setState는 reducer로 모으고, 상태 구조는 중복·모순이 없게 설계한다

기능

  1. 6커스텀 훅과 데이터 페칭 (TanStack Query)반복되는 훅 로직은 커스텀 훅으로 추출하고, 서버 데이터는 TanStack Query에 맡겨 캐시·재요청·상태 관리를 컴포넌트 밖으로 뺀다.
  2. 7폼 — 제어/비제어 컴포넌트와 검증입력값의 소유자를 React 상태로 둘지 DOM에 둘지 정하는 기준과, React 19 form action·useActionState로 검증·제출을 처리하는 방법
  3. 8라우팅(React Router)과 코드 분할React Router로 URL과 컴포넌트 트리를 대응시키고, lazy·Suspense·route.lazy로 번들을 라우트 단위로 쪼개는 방법을 정리한다

최신과 운영

  1. 9React 19 — Actions·use·Server Components폼 제출·비동기 상태·서버 렌더링을 React 19가 Actions, use, Server Components로 어떻게 언어 차원에서 흡수했는지 정리한다
  2. 10테스트(Testing Library)·TypeScript·배포React 앱을 사용자 관점 테스트·정적 타입·프로덕션 빌드로 안정적으로 운영하는 기준을 정리한다.

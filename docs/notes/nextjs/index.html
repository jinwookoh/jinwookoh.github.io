Next.js

App Router의 렌더링 모델, Server/Client Components, 데이터 페칭과 캐싱, Server Actions, Route Handler, 성능과 배포.

10편

기초

  1. 1Next.js란 — App Router와 렌더링 모델 (SSR·SSG·ISR·CSR)Next.js App Router는 라우트 단위로 정적·동적 렌더링을 자동 결정하며, 선택 기준은 데이터의 요청 의존성이다
  2. 2라우팅·레이아웃·로딩과 에러 UIApp Router는 폴더 규약만으로 중첩 레이아웃·스트리밍 로딩·구간별 에러 경계를 선언한다.
  3. 3Server Components와 Client Components서버 전용 렌더링을 기본으로 두고, 상호작용이 필요한 최소 범위에만 'use client' 경계를 긋는 기준을 정리한다

데이터

  1. 4데이터 페칭·캐싱·revalidateNext.js 15의 네 가지 캐시 계층과 fetch 옵션·revalidate·태그 무효화를 어떤 기준으로 조합하는지 정리한다
  2. 5Server Actions·폼·mutation폼 제출과 데이터 변경을 API 라우트 없이 서버 함수 하나로 처리하고 캐시까지 갱신하는 방법

기능

  1. 6Route Handlers·미들웨어·인증API 엔드포인트는 route.ts, 요청 전 분기는 middleware.ts, 실제 권한 검증은 데이터 접근 계층에 둔다.
  2. 7이미지·폰트·메타데이터·SEOnext/image·next/font·Metadata API로 레이아웃 시프트 없이 이미지·폰트를 서빙하고 SEO 태그를 코드로 관리하는 법
  3. 8스타일링과 상태 관리CSS는 import 순서가 곧 적용 순서이고, 상태는 서버 데이터·URL·클라이언트 UI 상태로 나눠 두어야 번들과 캐시가 무너지지 않는다

운영

  1. 9성능·번들·스트리밍Suspense 스트리밍으로 TTFB를 줄이고, 번들 분석기와 optimizePackageImports·dynamic으로 클라이언트 JS를 깎는 방법
  2. 10배포(Vercel·Docker)·환경변수·모니터링Next.js를 Vercel과 Docker 중 어디에 올리든 환경변수의 빌드·런타임 경계와 instrumentation 훅을 알아야 운영이 된다

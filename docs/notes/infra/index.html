인프라 — Kubernetes · Consul

Kubernetes의 아키텍처·워크로드·네트워킹·스토리지·보안·운영과 Consul 서비스 디스커버리·KV·서비스 메시.

10편

Kubernetes

  1. 1Kubernetes 아키텍처와 PodControl Plane과 Worker Node가 선언된 상태를 어떻게 유지하는지, 그 최소 단위인 Pod이 왜 휘발성인지 정리한다.
  2. 2Workloads — Deployment·StatefulSet·DaemonSet·JobPod을 직접 만들지 않고 컨트롤러에 맡겨야 하는 이유와, 다섯 가지 Workload를 상황별로 고르는 기준을 정리한다
  3. 3Services·Networking·IngressPod IP가 바뀌어도 접근 경로를 유지하는 Service·DNS·Ingress의 역할 분담과 노출 방식별 선택 기준
  4. 4ConfigMap·Secret·Storage설정은 ConfigMap·Secret으로 주입하고 데이터는 PVC·StorageClass로 영속화하되, Secret 평문과 Delete 회수 정책을 경계한다
  5. 5Scaling·Scheduling·ProbesHPA·Probe·Affinity·Taint·Quota로 Pod의 수·건강·배치·자원을 자동 제어하는 원리와 함정을 정리한다
  6. 6Security — RBAC·NetworkPolicyRBAC로 API 권한을, NetworkPolicy로 Pod 간 트래픽을, SecurityContext와 PSS로 컨테이너 권한을 최소화한다.
  7. 7Helm과 실전 운영 — 매니지드 K8s·CI/CD·Observability환경별 YAML 중복은 Helm 템플릿으로, 배포는 GitOps로, 상태 파악은 Metrics·Logs·Traces 3축으로 묶는다

Consul

  1. 8Consul 아키텍처와 배포 — Raft·Gossip·클러스터Consul 서버·클라이언트 모드가 Raft와 Gossip을 어떻게 나눠 쓰는지, 5 서버 클러스터를 어떤 구성으로 띄우는지 정리한다.
  2. 9Service Discovery와 KV StoreConsul에 서비스를 등록·조회하고 헬스 체크로 걸러내는 방식과, KV Store로 동적 설정·분산 락을 다루는 방법을 정리한다.
  3. 10Service Mesh·보안·백업Connect 사이드카·mTLS·Intentions로 서비스 간 통신을 통제하고, TLS·ACL·Gossip 키와 스냅샷으로 클러스터를 지킨다

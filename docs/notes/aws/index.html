AWS

IAM·컴퓨트·스토리지·네트워크·데이터베이스·메시징·서버리스·보안·모니터링·DR·CI/CD를 서비스 선택 기준 중심으로.

15편

기초와 보안

  1. 1IAM·STS·Cognito — 사용자·역할·정책AWS 권한은 정책 평가 순서·역할 수임·PassRole·Cognito 두 풀의 역할 분담을 알아야 안전하게 설계할 수 있다.
  2. 2KMS·SSM·Secrets Manager — 암호화와 비밀 관리KMS 봉투 암호화로 데이터를 잠그고, 설정은 Parameter Store에, 회전이 필요한 자격 증명은 Secrets Manager에 둔다.

컴퓨트와 스토리지

  1. 3EC2·EBS·EFSEC2 인스턴스 선택·구매 옵션·생명주기와 EBS·EFS·Instance Store를 워크로드 기준으로 고르는 규칙을 정리한다.
  2. 4ELB와 Auto ScalingALB·NLB·GWLB의 선택 기준과 ASG 스케일링 정책·Lifecycle Hook을 하나의 자가 치유 구조로 묶는다.
  3. 5S3 — 버킷·버전 관리·암호화·버킷 정책S3 버킷의 평면 키 구조와 버전 관리, 4종 서버 측 암호화, IAM·버킷 정책·BPA의 평가 순서를 정리한다
  4. 6S3 — 멀티파트·라이프사이클·복제대용량 객체를 병렬로 올리고, 시간에 따라 자동으로 옮기고 지우며, 다른 버킷에 비동기 복제하는 S3 운영 축을 정리한다.
  5. 7S3 — Object Lock·Access Points·CloudFront·Lambda 통합삭제 불가 보존, 버킷 하나에 여러 접근 경로, CDN 뒤로 버킷 숨기기, 업로드 이벤트 자동 처리를 S3 위에 어떻게 얹는가

네트워크와 데이터

  1. 8VPC·CloudFront·API GatewayVPC 경계 설계부터 CloudFront 캐싱, API Gateway 인증·스로틀링, Route 53 라우팅까지 트래픽 경로를 정리한다
  2. 9RDS·Aurora·DynamoDB관계형은 RDS·Aurora, 키-값 대규모 조회는 DynamoDB로 나누고 복제·캐시·키 설계 함정을 정리한다
  3. 10분석 — Athena·Glue·KinesisS3에 쌓인 로그를 옮기지 않고 SQL로 분석하고, Glue로 스키마와 포맷을 정리하고, Kinesis로 실시간 수집하는 파이프라인의 구성 원칙

서버리스와 통합

  1. 11SQS·SNS·Kinesis 메시징큐·Pub/Sub·스트림·이벤트 버스를 언제 고르고, 중복·순서·유실을 어디서 막는지 정리한다
  2. 12Lambda·SAM·Step Functions·ECS·Fargate코드를 함수로 올릴지 컨테이너로 올릴지 가르는 기준과, 각 선택에서 부딪히는 동시성·권한·시간 제한을 정리한다

운영

  1. 13CloudWatch·X-Ray·CloudTrail성능 지표는 CloudWatch, 요청 경로는 X-Ray, API 호출 기록은 CloudTrail로 역할을 나눠 운영 가시성을 확보한다.
  2. 14Multi-AZ 아키텍처·DR·마이그레이션단일 장애점을 제거하는 Multi-AZ 설계 원칙과 RPO·RTO 기준의 DR 4전략, DMS·MGN·Snowball 마이그레이션 조합을 정리한다
  3. 15CI/CD와 개발자 도구 — CodePipeline·CDK·CloudFormationCode* 파이프라인으로 배포를, CloudFormation·CDK로 인프라를 코드로 고정하는 방법

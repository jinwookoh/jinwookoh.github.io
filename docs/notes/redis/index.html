Redis

인메모리 데이터 구조 서버의 자료형·명령·캐싱과 락 패턴·영속성과 고가용성·보안·확장 모듈까지.

18편

기초

  1. 1Redis란 — 역할 분담과 CLI 첫걸음Redis는 PostgreSQL을 대체하지 않는 인메모리 키-값 계층이며, 단일 스레드 atomic 명령이 핵심 가치다.

데이터 타입

  1. 2데이터 타입 개관Redis 데이터 타입 13종의 용도를 매핑하고, 읽기·쓰기 패턴에 따라 어떤 타입을 골라야 하는지 정리한다.
  2. 3String·Hash — 값 캐싱과 객체 저장String은 값 하나·카운터·비트맵·락에, Hash는 부분 갱신이 잦은 flat 객체에 쓴다
  3. 4List·Set — 큐와 집합 연산List는 양 끝 O(1)의 큐, Set은 O(1) 멤버십과 집합 연산 — 언제 어느 쪽을 쓰고 어디서 무너지는가
  4. 5Sorted Set — 랭킹과 Rate Limiterscore가 붙은 집합 하나로 Top N 랭킹·순위 조회·Sliding Window Rate Limiter·우선순위 큐를 O(log N)에 처리한다
  5. 6Stream·Pub/Sub — 영속 로그와 실시간 전파손실이 허용되는 실시간 신호는 Pub/Sub, 재처리와 ACK가 필요한 이벤트는 Stream Consumer Group으로 처리한다

명령과 스크립트

  1. 7TTL·Eviction·Keyspace Notification키 수명은 TTL, 메모리 한계는 maxmemory-policy, 만료 후속 처리는 Keyspace Notification이 맡되 각각의 정확성 한계를 안다
  2. 8Pipelining·Transaction·WATCHPipelining은 왕복을 줄이고 MULTI/EXEC는 격리만 보장한다. 롤백은 없고 조건부 갱신은 WATCH 재시도로 푼다.
  3. 9Lua Scripting과 Functions조건부 로직을 서버 안에서 원자적으로 묶는 EVAL과, 그 휘발성·익명성을 없앤 Redis 7 Functions의 사용법과 함정

패턴

  1. 10캐싱 패턴 — Cache-Aside·스탬피드·Hot Key캐시 읽기·쓰기 패턴 4종을 비교하고, 동시 만료 폭주와 단일 키 쏠림을 락·조기 갱신·지터·키 분산으로 막는 방법을 정리한다.
  2. 11분산 락 — SET NX와 Redlock단일 인스턴스 SET NX 락이 보장하는 것과 못 하는 것, Redlock의 quorum 모델과 fencing token이 필요한 경계를 정리한다.
  3. 12Secondary Index·Fanout·분산 ID키-값 모델에서 속성 조회·팔로워 피드·충돌 없는 ID를 자료구조 조합으로 풀어내는 세 가지 패턴

운영

  1. 13Persistence — RDB·AOF·HybridRDB 스냅샷·AOF 로그·Hybrid의 RPO/RTO 트레이드오프와 fsync 정책, fork 비용을 기준으로 영속화 옵션을 고른다.
  2. 14Replication과 Sentinel비동기 복제로 읽기를 분산하고 Sentinel의 quorum 합의로 master 장애를 자동 승격하는 원리와 함정
  3. 15Cluster와 일관된 해싱단일 인스턴스의 메모리·쓰기 한계를 넘기 위한 샤딩 — 해시 링과 16384 슬롯이 키 이동을 최소화하는 원리
  4. 16보안 — ACL·TLSdefault 사용자 잠금과 ACL 최소 권한, 그리고 클라이언트·복제·클러스터 버스까지 TLS로 닫는 방법
  5. 17메모리 최적화와 클라이언트 (Jedis·Lettuce)인코딩 임계값과 키 오버헤드로 메모리를 줄이고, 연결 모델 차이로 Jedis와 Lettuce를 고르는 기준을 정리한다.

확장 모듈

  1. 18확장 모듈 — JSON·Search·TimeSeries·Vector기본 자료구조로 흉내내던 문서·검색·시계열·벡터 워크로드를 Redis 모듈이 어떻게 1급으로 처리하는지 정리한다

Reactive Spring

Project Reactor의 Mono·Flux·연산자·Backpressure부터 WebFlux·R2DBC·리액티브 Redis·RSocket·gRPC·GraphQL까지.

24편

Reactor 기초

  1. 1리액티브 프로그래밍 — 왜 필요한가·Reactive Streams스레드당 요청 모델의 한계를 Reactive Streams 명세와 이벤트 루프가 어떻게 넘어서는지 정리한다
  2. 2Mono와 FluxMono는 0~1개, Flux는 0~N개를 지연 방출하는 Publisher이며 팩토리·변환·에러 처리 연산자의 선택 기준을 정리한다.
  3. 3연산자 — 변환·결합·배칭flatMap·zip·buffer 계열 연산자를 순서·동시성·완료 조건이라는 세 축으로 골라 쓰는 기준을 정리한다

Reactor 심화

  1. 4Hot/Cold Publisher와 Sinks구독마다 소스를 다시 실행하는 Cold를 Hot으로 바꾸는 연산자와, 외부에서 직접 신호를 주입하는 Sinks의 선택 기준을 정리한다
  2. 5Backpressure생산 속도가 소비 속도를 앞지를 때 request(n)과 오버플로우 전략으로 메모리 고갈을 막는 방법을 정리한다.
  3. 6Schedulers·스레딩·ContextReactor는 기본이 동기 실행이다. 스레드는 Schedulers로 옮기고, 요청 범위 데이터는 ThreadLocal 대신 Context로 전파한다.
  4. 7Repeat·Retry와 StepVerifier완료·에러 후 재구독하는 repeat/retry 전략과, 비동기 파이프라인을 가상 시간으로 검증하는 StepVerifier 사용법

WebFlux

  1. 8WebFlux 기본 — 애노테이션 컨트롤러와 Functional Endpoints같은 WebFlux 위에서 @RestController와 RouterFunction이 어떻게 다르고 언제 무엇을 고르는지 정리한다
  2. 9WebClient이벤트 루프를 막지 않고 외부 HTTP를 호출하는 WebClient의 설정·응답 처리·에러·타임아웃·재시도 패턴을 정리한다.
  3. 10WebFilter·예외 처리·검증WebFilter로 공통 처리를 모으고, Bean Validation과 ProblemDetail로 실패 응답을 일관되게 만드는 방법
  4. 11스트리밍 응답 — SSE·NDJSONFlux 반환만으로는 스트리밍이 되지 않는다. produces가 응답 형식을 결정하고 NDJSON과 SSE는 용도가 다르다.
  5. 12WebFlux 성능과 마이크로서비스이벤트 루프를 막지 않는 설정과 서비스 조합 패턴을 갖춰야 WebFlux의 처리량이 실제로 나온다.

리액티브 데이터

  1. 13R2DBC — 리액티브 DB 연동과 JPA 비교WebFlux 이벤트 루프를 막지 않는 DB 접근 방법과, JPA에서 사라지는 것·얻는 것의 경계를 정리한다
  2. 14리액티브 Redis — 연동·Template·자료구조WebFlux에서 Lettuce 기반 ReactiveRedisTemplate으로 Redis를 연동하고 5대 자료구조를 논블로킹으로 다루는 방법을 정리한다.
  3. 15리액티브 Redis — 캐싱·Pub/Sub·트랜잭션·성능WebFlux에서 Redis를 캐시·메시지 버스·원자 연산 수단으로 쓸 때 맞는 패턴과 성능이 새는 지점

RSocket

  1. 16RSocket — 개념·프레임·Interaction ModelRSocket이 단일 연결 위에서 REQUEST_N 백프레셔와 4가지 Interaction Model로 서비스 간 통신을 처리하는 원리
  2. 17RSocket — 서버·클라이언트·메타데이터 라우팅Spring에서 @MessageMapping 서버와 RSocketRequester 클라이언트를 만들고 라우트·인증·trace를 Composite Metadata로 싣는 방법
  3. 18RSocket — 보안·로드 밸런싱·테스트영구 연결 프로토콜인 RSocket을 SETUP 인증·TLS·클라이언트 사이드 LB·StepVerifier로 운영 수준까지 끌어올리는 방법

gRPC

  1. 19gRPC — 개념·HTTP/2·ProtobufgRPC는 Protobuf 스키마와 HTTP/2 전송을 결합한 RPC이며, 필드 번호가 와이어 호환성을 결정한다.
  2. 20gRPC — Unary·Server/Client/Bidirectional StreaminggRPC 4가지 RPC 모드가 StreamObserver 하나로 어떻게 구분되고, 각각 언제 쓰는지 정리한다
  3. 21gRPC — 에러·인터셉터·보안·운영Status Code로 재시도 가능 여부를 표현하고, 인증·로깅은 인터셉터로 분리하며, 운영에서는 mTLS·Health Check·KeepAlive를 갖춘다

GraphQL

  1. 22GraphQL — Schema·Query·Mutation·Spring for GraphQLGraphQL은 스키마를 계약으로 두고 클라이언트가 필요한 필드만 명시하며, Spring for GraphQL은 이를 애노테이션 컨트롤러로 매핑한다.
  2. 23GraphQL — 리액티브 통합과 SubscriptionSpring for GraphQL은 Mono/Flux 반환을 그대로 처리하며, Subscription은 Flux 하나와 Sinks·Pub/Sub 조합으로 실시간 스트림이 된다
  3. 24GraphQL — DataLoader·Federation·보안·테스트DataLoader로 N+1을 잡고, Depth·Complexity 제한과 필드 권한으로 단일 엔드포인트를 지키며, GraphQlTester로 검증한다

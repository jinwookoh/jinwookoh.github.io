실무 워크플로 — 계획·TDD·비용 관리

컨텍스트를 유한한 자원으로 다루는 계획·검증·정리 습관과 토큰 비용을 줄이는 조치

한 세션에 서로 다른 작업을 이어 붙이면 어느 순간부터 앞에서 준 지시를 잊고 엉뚱한 파일을 고치기 시작한다. 원인은 컨텍스트 윈도다. 대화 전체와 읽은 파일, 명령 출력이 매 요청에 함께 실려 나가고, 채워질수록 판단이 흐려진다. 디버깅 한 번이나 코드베이스 탐색 한 번이 수만 토큰을 만든다. 실무 워크플로 규칙은 대부분 이 하나의 제약에서 파생된 결과다.

핵심 개념

작업이 끝났는지 판단하는 기준부터 정한다. 모델은 "다 된 것처럼 보일 때" 멈추므로 스스로 돌릴 수 있는 검사가 없으면 사람이 검증 루프가 된다. 테스트 스위트, 빌드 종료 코드, 린터, 기준 이미지와 비교할 스크린샷처럼 통과와 실패가 갈리는 신호를 쥐여 주면 루프가 스스로 닫힌다. 강도는 세 단계다. 프롬프트 안에서 검사까지 돌리라고 시키거나, /goal 조건으로 걸어 매 턴 재평가하게 하거나, Stop 훅으로 검사가 통과할 때까지 턴 종료를 막는다. Stop 훅은 8번 연속으로 턴을 막으면 무시되고 턴이 그대로 끝난다.

테스트를 먼저 세우는 방식은 이 검증 루프를 가장 싸게 만드는 길이다. 기대하는 입출력을 프롬프트에 미리 적어 실패하는 테스트부터 쓰게 하고, 구현이 없는 상태에서 실패를 확인한 뒤 통과할 때까지 고치게 한다. 다만 한 세션에서 작성과 검토를 모두 시키면 방금 만든 코드에 유리한 쪽으로 판단이 기운다. 검토는 계획서와 diff만 보는 새 컨텍스트의 서브에이전트에 맡기고, 무엇을 결함으로 볼지 범위를 함께 지정한다.

구현 전에 탐색과 계획을 분리한다. Shift+Tab 을 눌러 계획 모드로 들어가거나 claude --permission-mode plan 으로 시작하면 파일을 읽고 계획만 세운다. Ctrl+G 로 계획을 편집기에서 직접 고친 뒤 승인한다. 다만 계획 모드에도 비용이 있다. 바꿀 내용을 한 문장으로 설명할 수 있으면 건너뛰고, 여러 파일에 걸치거나 낯선 코드를 만질 때만 쓴다.

방향이 틀어지면 즉시 끊는다. Esc 는 진행 중인 동작만 멈추고 컨텍스트는 남긴다. Esc 두 번 또는 /rewind 는 대화와 코드를 이전 체크포인트로 되돌린다. 같은 문제로 두 번 이상 교정했다면 컨텍스트가 실패한 접근으로 오염된 상태이므로, /clear 로 비우고 그동안 알아낸 것을 반영한 프롬프트로 다시 시작하는 편이 빠르다. 무관한 작업 사이에는 항상 /clear 를 넣는다.

비용은 컨텍스트 크기에 비례한다. /usage 로 세션 토큰과 프롬프트 캐시 적중률을 본다. 엔터프라이즈 배포 기준 평균은 개발자 한 명당 활성일 13달러, 월 150~250달러 수준이고 사용자의 90%가 하루 30달러 아래에 머문다. 줄이는 방법은 대체로 컨텍스트를 줄이는 방법과 같다. 대부분의 코딩 작업은 Sonnet으로 충분하고 Opus는 아키텍처 판단에 남긴다. 장황한 출력이 나오는 조사와 테스트 실행은 서브에이전트에 맡겨 요약만 돌려받는다. MCP 서버보다 gh 나 aws 같은 CLI 도구가 컨텍스트를 덜 먹는다.

CLAUDE.md는 매 세션 로드되므로 200줄 아래로 유지하고, 가끔만 필요한 도메인 지식과 절차는 스킬로 옮겨 호출될 때만 붙게 한다. Java/Spring에 대응시키면 CLAUDE.md는 항상 로드되는 공통 설정, 스킬은 필요한 프로파일에서만 활성화되는 설정에 가깝다. 훅은 권고가 아니라 반드시 실행되는 필터에 해당한다.

코드

CLAUDE.md에는 코드를 읽어서 알 수 없는 것만 남긴다. 표준 관례나 일반론은 넣지 않는다.

# 명령
- 테스트: `./gradlew test --tests '*ServiceTest'` (전체 실행 금지, 느림)
- 마이그레이션: `./gradlew flywayMigrate -Denv=local`

# 규칙
- 엔티티에 setter 추가 금지, 정적 팩터리로 생성
- 변경 후 반드시 `./gradlew compileJava` 로 타입 확인

# 압축 지침
- compact 시 수정한 파일 목록과 실행한 테스트 명령은 반드시 보존

훅으로 도구 출력 자체를 줄이면 컨텍스트가 크게 절약된다. 테스트 명령을 가로채 실패 줄만 남기는 PreToolUse 훅이다.

{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          { "type": "command", "command": "~/.claude/hooks/filter-test-output.sh" }
        ]
      }
    ]
  }
}

계획 모드로 시작하고, 병렬 작업은 워크트리로 분리하고, 반복 작업은 비대화형 실행으로 돌린다.

claude --permission-mode plan
claude --worktree feature-auth
git log --oneline -20 | claude -p "최근 커밋을 요약해라"

실무에서 걸리는 지점

  • 체크포인트는 Claude의 파일 편집 도구를 거친 변경만 되돌린다. Bash 명령이나 외부 프로세스가 만든 변경은 /rewind 로 복구되지 않는다. 되돌릴 수 있어야 하는 작업은 git 커밋으로 따로 고정한다.
  • 프롬프트 캐시 수명은 구독에서 한 시간이지만 API 키나 클라우드 제공자에서는 기본 5분이다. 휴식 뒤 첫 메시지가 캐시를 놓치면 전체 대화를 다시 처리하므로, 오래 열어 둔 세션은 사용량이 활동량보다 훨씬 빨리 오른다.
  • CLAUDE.md가 길어지면 규칙이 묻힌다. 같은 지시를 계속 무시당한다면 그 지시의 문제가 아니라 파일이 길다는 신호로 읽고 줄인다.
  • 리뷰어 서브에이전트는 찾으라고 시키면 무엇이든 찾아낸다. 정확성과 명시한 요구사항에 한정하지 않으면 불필요한 추상화와 방어 코드가 붙는다.
  • 에이전트 팀은 팀원이 계획 모드로 돌 때 일반 세션의 약 7배 토큰을 쓴다. 팀원마다 독립된 컨텍스트 윈도를 유지하므로, 작업을 작고 자족적으로 쪼개고 끝난 팀원은 바로 종료한다.

TypeScript

타입 시스템과 컴파일 파이프라인, 제네릭·유니온·유틸리티 타입, 모듈과 빌드 설정, strict 모드 실무 패턴.

8편

기초

  1. 1왜 TypeScript인가 — 타입 시스템과 컴파일 파이프라인TypeScript는 JavaScript에 정적 타입 검사를 얹어 실행 전에 오류를 잡고, 컴파일 시 타입을 지워 순수 JS를 내보낸다.
  2. 2기본 타입·인터페이스·타입 별칭원시 타입·객체 타입을 어떻게 선언하고, interface와 type alias를 언제 골라 쓰는지 정리한다

타입 시스템

  1. 3제네릭제네릭은 타입을 매개변수로 받아 입력과 출력의 관계를 보존하는 장치이며 제약·추론·기본값이 핵심이다
  2. 4유니온·교차·리터럴 타입과 Narrowing유니온으로 가능한 값의 집합을 선언하고, 제어 흐름 분석으로 각 분기에서 타입을 좁혀 캐스팅 없이 안전하게 다룬다.
  3. 5유틸리티 타입·조건부 타입·매핑 타입기존 타입에서 새 타입을 파생하는 세 가지 도구의 동작 원리와 실무 함정을 정리한다.
  4. 6클래스·데코레이터·모듈TypeScript 클래스의 타입 규칙, 표준 데코레이터와 legacy 데코레이터의 차이, ESM 기반 모듈 타입 모델을 정리한다

빌드와 실무

  1. 7tsconfig·빌드·ESM과 CJSmodule·moduleResolution·verbatimModuleSyntax가 ESM/CJS 출력을 어떻게 결정하는지 정리한다
  2. 8실무 패턴 — strict 모드·타입 가드·에러 처리strict 옵션을 켜고, 타입 가드로 좁히고, unknown 기반으로 에러를 다루는 실무 규칙을 정리한다

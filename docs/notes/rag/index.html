RAG

검색 증강 생성 — 임베딩·벡터 DB·청킹·하이브리드 검색·리랭킹, GraphRAG와 온톨로지, 평가와 프로덕션 운영.

10편

기초

  1. 1RAG란 무엇인가 — LLM의 한계와 검색 증강 생성RAG는 질문 시점에 관련 문서를 찾아 프롬프트에 붙이는 구조이며, 품질은 검색 단계가 결정한다
  2. 2임베딩과 벡터 유사도 검색임베딩은 텍스트를 의미 좌표로 바꾸며, 검색 품질은 모델 선택과 질의·문서 처리의 대칭에서 갈린다
  3. 3벡터 데이터베이스 — pgvector·전용 벡터 스토어 선택벡터 저장소 선택은 규모보다 필터 요구와 운영 부담이 가르며, ANN 인덱스 파라미터가 재현율을 결정한다

검색 파이프라인

  1. 4청킹과 인덱싱 전략청크는 검색 단위이자 생성 단위이며, 둘을 분리하고 증분 인덱싱을 설계해야 운영이 굴러간다
  2. 5하이브리드 검색과 리랭킹BM25와 벡터 검색을 RRF로 합치고 cross-encoder 리랭커로 다시 정렬해 상위 k개의 정확도를 끌어올린다
  3. 6쿼리 변환 — 멀티 쿼리·HyDE·라우팅사용자 질의를 그대로 검색하지 않고 재작성·확장·분해·라우팅해 검색 단계의 recall을 끌어올린다

그래프와 온톨로지

  1. 7GraphRAG — 지식 그래프 기반 검색 증강여러 문서에 흩어진 사실과 코퍼스 전역 요약 질의를 지식 그래프와 커뮤니티 요약으로 답하는 구조를 정리한다
  2. 8온톨로지와 지식 그래프 모델링 — RDF·OWL·프로퍼티 그래프RDF·OWL의 트리플과 공리, 프로퍼티 그래프의 레이블·관계를 비교해 어느 쪽으로 지식 그래프를 설계할지 정리한다

운영

  1. 9RAG 평가 — 검색 품질과 생성 품질을 따로 잰다검색 단계와 생성 단계를 분리해 지표를 세우고 회귀를 잡는 RAG 평가 파이프라인을 정리한다
  2. 10프로덕션 RAG — 캐싱·비용·보안·에이전틱 패턴프롬프트 캐싱과 검색 파라미터로 비용을 잡고 권한·인젝션을 막으며 에이전틱 검색을 예산 안에 가두는 방법을 정리한다
